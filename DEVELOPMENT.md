# Development

The existing .NET 10 Synthesis project uses Mutagen.Bethesda.Synthesis 0.36.6 and Mutagen.Bethesda.Skyrim 0.54.4.

- `Program.cs` registers the autogenerated Synthesis settings and passes the pipeline's winning-record link cache and output mod to the patcher. Both modes use the ordinary Synthesis export path.
- `PatcherSettings.cs` defines the race list and the three-state flag setting. Race keys are stored as text so a malformed key can be reported and skipped while processing other entries. Mutagen parses the text and resolves the resulting FormKey as a race.
- `RaceFlagPatcher.cs` evaluates entries against the winning records before writing any overrides. Both modes use the resulting `RaceEvaluation` entries to report changes and build the summary. Only patch mode writes overrides for entries that require a change.
- `RacePatchReport.cs` defines the structured evaluation and counters. Resolved races include changes, already-matching entries, and entries set to `Unchanged`. Unresolved, duplicate, and invalid entries have separate counts.

To add a race flag, add an explicit `FlagChange` field defaulting to `Unchanged`. Extend the flag calculation and report the before and after values of each changed flag. Keep the override decision after all requested changes have been calculated.

The MSTest suite uses in-memory Skyrim mods, including a later override with its own flag and EditorID values. Run it with `dotnet test`. In environments that restrict named pipes, run the test executable directly with `dotnet run --project RaceTweaksPatcher.Tests`.

## Verify the CLI dry-run

Enable **Dry Run** in Synthesis's patcher settings or put `{"DryRun":true}` in the `settings.json` under the CLI's `--ExtraDataFolder`. Run the built patcher using a Skyrim SE data directory and a load order file for that installation.

```powershell
dotnet .\RaceTweaksPatcher\bin\Release\net10.0\RaceTweaksPatcher.dll run-patcher `
  --GameRelease SkyrimSE --DataFolderPath "<Skyrim Data directory>" `
  --LoadOrderFilePath "<plugins.txt>" --ExtraDataFolder "<settings directory>" `
  --ModKey RaceTweaksPreview.esp --OutputPath "<scratch directory>\RaceTweaksPreview.esp"
```

Synthesis requires an output path argument in both modes. With a vanilla GiantRace winner the dry-run report shows one proposed change and zero overrides written. Expect exit code zero and a valid ESP with no race records. If the run supplies a preceding patch via `--SourcePath`, the export carries its records forward. Use a scratch output because Synthesis writes to the requested destination in either mode. Run with `DryRun` set to `false` and a separate scratch output to verify the matching normal patch.

## Dry-run completion in Synthesis 0.36.6

The earlier dry-run set `PatcherPreferences.NoPatch`. The patcher process printed `Finished patch.`, returned exit code zero, and skipped serialization. An ordinary patch with an already-matching flag also returned zero and exported an empty ESP. The desktop runner's finalizer reports success when the expected output or split output exists. Without a file, it returns without a success event, which explains the lingering patcher row. [Synthesis output finalizer](https://github.com/Mutagen-Modding/Synthesis/blob/0.36.6/Synthesis.Bethesda.Execution/Running/Runner/FinalizePatcherRun.cs)

The patcher now lets Synthesis serialize the existing output mod in dry-run. The race evaluator still skips all writes in that mode. The subprocess regression tests use synthetic Skyrim plugins to verify bounded process exit, a readable empty ESP for a standalone dry-run, preservation of an earlier patcher's race record in the exported output, and both ordinary no-op and changing patch runs.

Validation against the installed Skyrim master confirmed that dry-run and normal no-op both exported empty ESPs. The installed Synthesis 0.36.6 finalizer emitted a success event for both outputs and emitted none for the original dry-run's missing output.
